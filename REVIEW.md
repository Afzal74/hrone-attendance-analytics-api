I reviewed the starter against `openapi.yaml` and `DATA_MODEL.md`. The following defects were identified in the supplied implementation.

| #   | Where                                                                      | What is wrong                                                                                                                                                                                                          | How to notice it                                                                                                                 | How it was fixed                                                                                                                                                            |
| --- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `health()`                                                                 | Always returns 200 without checking MongoDB availability.                                                                                                                                                              | Stop MongoDB and call `/health`; it still reports ready.                                                                         | Ping MongoDB and return 503 on a database error.                                                                                                                            |
| 2   | Startup                                                                    | No application indexes are created.                                                                                                                                                                                    | Inspect `getIndexes()` on a fresh database.                                                                                      | Added idempotent unique and query-supporting indexes during application lifespan startup.                                                                                   |
| 3   | `EmployeeIn`                                                               | Does not enforce required formats, field lengths, valid joining dates, or different shift start and end times.                                                                                                         | Submit an employee with an invalid email, date, shift time, or identical shift times.                                            | Added Pydantic constraints and date/shift validation.                                                                                                                       |
| 4   | `create_employee()`                                                        | Check-then-insert is race-prone, and duplicate-key errors are not handled.                                                                                                                                             | Send concurrent requests creating the same `emp_code`.                                                                           | Rely on a unique database index and translate `DuplicateKeyError` to HTTP 409.                                                                                              |
| 5   | `create_employee()`                                                        | Stores `created_at` as a naive datetime and does not return it in the required epoch-millisecond format.                                                                                                               | Inspect the stored value and the API response for `created_at`.                                                                  | Store a normalized UTC BSON datetime and use the shared serializer to return epoch milliseconds.                                                                            |
| 6   | `list_employees()`                                                         | Uses `skip = page * page_size`, which skips the first page; `total` ignores the department filter, and results lack the required sorting.                                                                              | Request page 1 or filter employees by department.                                                                                | Use `(page - 1) * page_size`, count matching filtered records, and sort by `emp_code`.                                                                                      |
| 7   | `punch_in()`                                                               | Unknown employees can cause a server error, and timestamp and status validation are incomplete.                                                                                                                        | Punch in with an unknown employee, a seconds-based timestamp, or an invalid status.                                              | Added 404 handling and strict epoch-millisecond and status validation.                                                                                                      |
| 8   | `punch_in()`                                                               | Uses local, naive timestamps and the local calendar date, leading to incorrect IST dates and overnight-shift handling.                                                                                                 | Punch in around midnight or test a `22:00–06:00` shift.                                                                          | Normalize instants to UTC, derive attendance dates in IST, and handle overnight shifts.                                                                                     |
| 9   | `punch_in()` concurrency and response                                      | Check-then-insert is unsafe under concurrent requests, and the response exposes an unsupported attendance `id`.                                                                                                        | Send simultaneous punch-ins or inspect the attendance response JSON.                                                             | Enforce a unique `(emp_code, date)` index, handle duplicate-key conflicts as 409, and return only contract-defined fields.                                                  |
| 10  | `compute_late_minutes()`, `compute_work_hours()`, and `compute_overtime()` | The late calculation mishandles the exact R2 grace boundary; work hours use Python `round()` instead of the required HALF_UP rounding; overtime lacks the 30-minute minimum; overnight shift boundaries are incorrect. | For a 09:30 shift, test a 09:40:01 punch-in; also test half-cent rounding, overtime below 30 minutes, and a `22:00–06:00` shift. | Compare exact elapsed seconds against 600 for R2, use `Decimal` with `ROUND_HALF_UP`, enforce the 30-minute overtime threshold, and centralize shift-boundary calculations. |
| 11  | `list_attendance()`                                                        | Loads all matching records into Python and sorts them there, which is inefficient at the required scale.                                                                                                               | Run against approximately 100,000 attendance records.                                                                            | Perform filtering, sorting, counting, skipping, and limiting in MongoDB, supported by indexes.                                                                              |
| 12  | `list_attendance()`                                                        | Has incomplete date-range, status, and pagination validation; lacks the required deterministic sort tie-breaker; and does not fully handle legacy defaults or timestamp conversion.                                    | Test invalid date ranges, page 0, invalid statuses, equal-date records, legacy documents, and timestamp response fields.         | Added parameter validation, database-side sorting by date descending and `emp_code` ascending, pagination, default values, and recursive serialization.                     |

## Existing design choices retained

- The FastAPI, Pydantic, and MongoDB stack was appropriate, so it was retained.
- Employee identity remains `emp_code`, not MongoDB's internal `_id`.
- Attendance records remain identified by `(emp_code, date)`; attendance IDs are not exposed by the API.
- The supplied seed format follows the documented MongoDB data model, so the seed data was not changed.
